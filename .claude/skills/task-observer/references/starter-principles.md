# Optional review principles

- Evidence precedes acceptance; a transport completion is not a passed task.
- Preserve one controller for task states and retry decisions.
- Respect authorization denials, and keep transient retries bounded.
- Prefer small, testable instruction changes and retain the previous baseline.
- Keep project-specific knowledge local; promote only reviewed general lessons.
- Avoid duplicate logging and loading full reference documents without a current need.
- State verification limits honestly; a package shape check is not a live provider pilot.

These principles guide review. They do not replace project requirements, user authorization,
current task acceptance criteria, or the controller's policy.
